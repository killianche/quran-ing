# Quran Ing в Google Play

> **TL;DR.** Подписанные AAB/APK собирает `.github/workflows/android-release.yml`
> (Actions → Android release → Run). Ключ загрузки — `secrets/android/` на
> сервере (вне git) и секреты репозитория `ANDROID_*`. Картинки — `play-store/`.
> Приложение в Play Console создаёт и первую сборку загружает владелец
> (у Google нет API для создания приложения); дальше выгрузку можно
> автоматизировать сервисным аккаунтом.
>
> **Имя для запроса:** «выложи в Play», «собери андроид», «плеймаркет».

### Рекомендации Play Console (не блокируют)

- «Edge-to-edge may not display…» и «deprecated APIs for edge-to-edge» —
  устаревшие вызовы (`Window.setStatusBarColor`, `SYSTEM_UI_FLAG_*`) внутри
  официальных плагинов `@capacitor/status-bar` 8.0.3 и `splash-screen` 8.0.2,
  не в нашем коде. В 8.0.4 status-bar Android-код тот же (сверено
  2026-10-06) — обновление не поможет. Раскладка при этом защищена:
  Capacitor 8 `SystemBars` (insetsHandling `css`) на WebView ≥ 140 отдаёт
  отступы в `env()`, на старых — сам отодвигает веб-вью от панелей.
  Вернуться, когда плагины обновят.
- «R8 optimization» — `minifyEnabled false` сознательно: плагины Capacitor
  работают через рефлексию, а почти весь размер AAB — шрифты, не код.

## Сборка

```
Actions → Android release → Run workflow
```

Артефакт `quran-ing-android-release` (30 дней):

- `app-release.aab` — для Play Console;
- `app-release.apk` — поставить на телефон напрямую (разрешить установку из
  неизвестных источников).

Проверки в workflow: тесты, сакральный гард, подпись AAB (jarsigner) и APK
(apksigner), выравнивание 16 КБ (требование Play для targetSdk 35+).
targetSdk = 36.

**Ключ.** Upload key `upload` (RSA 4096, до 2056), SHA-256 сертификата:
`F9:B0:CE:A5:D9:A7:56:17:0C:9A:51:16:DA:B0:E9:B7:50:ED:C2:D7:40:8F:20:72:1E:C7:DF:3C:69:82:7B:2D`.
В Play включается **подпись приложений Google Play** (Play App Signing):
ключ приложения хранит Google, наш ключ — только для выгрузок, при утере
сбрасывается через поддержку Play. Резервная копия `secrets/android/` —
обязанность владельца.

## Шаги владельца в Play Console

1. **Создать приложение:** название `Quran Ing`, язык по умолчанию — русский,
   «Приложение», «Бесплатное», отметить декларации.
2. **Тестирование → Закрытое (или Внутреннее) тестирование → Создать
   выпуск:** загрузить `app-release.aab`, подтвердить подпись Google Play.
   - Личный аккаунт, созданный после 13.11.2023: до выхода в «Рабочую версию»
     Google требует закрытый тест — **не меньше 12 тестировщиков 14 дней
     подряд**, затем заявку на доступ к рабочей версии. У аккаунта
     организации этого требования нет. (Сверить с текстом в консоли.)
3. **Настройка приложения** — ответы ниже.
4. **Основная страница в магазине** — тексты и картинки ниже.

### Безопасность данных — почему «не собираются»

Сверено по коду 2026-10-05: приложение ходит в сеть только за аудио
(`download.quranicaudio.com`, `everyayah.com`, `cdn.islamic.network`,
`server8.mp3quran.net`, `l.asrbook.ru`, хранилище записей Мержоева).
Время намаза и кибла считаются на устройстве; геопозиция, закладки,
настройки никуда не отправляются. Аналитики, рекламы и аккаунтов нет.
По правилам Google данные, которые обрабатываются только на устройстве,
не считаются «собранными». Шифрование при передаче — HTTPS.

### Разрешения, которые увидит проверка

- `ACCESS_FINE/COARSE_LOCATION` — время намаза и кибла по месту; только на
  устройстве, по запросу человека.
- `SCHEDULE_EXACT_ALARM` — напоминания о намазе в точную минуту (основная
  функция раздела «Намаз»).
- `POST_NOTIFICATIONS` — напоминания и уведомление-плеер.
- `FOREGROUND_SERVICE*` сняты 2026-10-05: службы нет, а за объявленный тип
  Play требует декларацию с видео.

## Автоматическая выгрузка — настроена 2026-10-05

Сервисный аккаунт `quran-ing-publisher@xtrud-play.iam.gserviceaccount.com`
(проект Google Cloud `xtrud-play` владельца), в Play Console — доступ только
к Quran Ing. Ключ — `secrets/xtrud-play-723337e56c46.json`, путь —
`secrets/play.env`. Проверено: API видит `ing.quran.app` (язык ru-RU, треки
пусты).

```
. secrets/play.env
node scripts/play/play-publish.mjs --aab app-release.aab [--track production] [--status draft]
node scripts/play/play-publish.mjs --listing-only
```

Тексты страницы для скрипта — `play-store/listing-ru.json` (источник
правды; таблица выше — для чтения). Пока приложение не опубликовано —
только `draft`, на проверку отправляет владелец в консоли.

## Прежняя заметка: как настраивался доступ

Google Cloud → сервисный аккаунт с ключом JSON → Play Console → «Пользователи
и разрешения» → пригласить его почту с правами на Quran Ing (выпуски) →
ключ — в `secrets/` и секреты репозитория. После первой ручной загрузки
сборки выкладываются скриптом (Google Play Developer API, edits.bundles).
