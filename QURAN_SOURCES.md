# Реестр кораничных источников

Требование `CLAUDE.md` (сакральные правила, §9): всё, что цитирует Коран,
должно быть перепроверяемо одним проходом — с указанием издания, откуда
взят текст, и даты получения.

## Основной источник текста

Весь кораничный текст приложения берётся из одного места —
`src/content/quran-sources.ts`. Это машинный реестр на **6236 аятов**, по
одной записи на аят:

| Поле | Что в нём |
|---|---|
| `arabic` | арабский, edition `ar-simple-clean` |
| `translations.ru` | перевод, edition `ru-kuliev` (Эльмир Кулиев) |
| `translations.inh` | ингушский перевод смыслов (см. раздел «Ингушский перевод») |
| `editions` | какие именно издания использованы |
| `fetchedAt` | дата получения записи |

Русский перевод в проекте один — **Кулиев**. Другие русские переводы не
используются нигде: единый голос важнее разнообразия, иначе читатель
встречает разную стилистику в разных углах приложения.

перераспространение. Перед `Submit for Review` каждый статус `Нужно подтвердить`
должен стать `Подтверждено` со ссылкой и сохранённой копией разрешения либо

набором и не удаляется.

## Разметка мусхафа QCF V1 «Мадани 1405»

Постраничный мусхаф V1 показывает страницу 1:1 с печатным изданием, и для
этого нужны две вещи: какое слово на какой строке и чем набраны заголовок
суры с басмалой. Первое отдаёт API, второе — нет, ни при каком значении
параметра `mushaf`.

| Что | Откуда | Дата |
|---|---|---|
| Слова аятов, разбиение по строкам | `api.qurancdn.com/api/qdc/verses/by_page/{N}?mushaf=2` | 2026-08-31 |
| Строки заголовков сур и басмалы | `github.com/quran/quran.com-images`, `sql/02-database.sql` + патч `sql/03-basmallah-shaddah.sql` | 2026-08-31 |
| Начертания | `public/qcf1/fonts-woff2/` — уже в проекте, новых файлов не добавлялось | ранее |

Второй источник — оригинальный генератор постраничных картинок V1, которым
пользовались quran.com и его мобильные приложения. В нём лежит тот же самый
шрифт `QCF_BSML` и таблицы `glyph` / `glyph_page_line` с типом строки
`sura` / `ayah` / `bismillah`.

### Что проверено перед тем, как это попало в приложение

Сакральный текст не принимается на веру ни от источника, ни от агента.
Прогонялось вживую:

- Разметка сплошная: 604 страницы, строки без дыр, по 15 на странице и по 8
  на первых двух.
- **114 строк заголовков и ровно 112 строк басмалы.** Разница в две штуки
  осмысленна и служит проверкой сама по себе: у Аль-Фатихи басмала — это
  первый аят, у Ат-Тауба басмалы нет вовсе.
- Все 125 использованных кодов присутствуют в нашем файле шрифта и реально
  прорисованы.
- Отрисовка прочитана глазами: سُورَةُ الفَاتِحَةِ, سُورَةُ المَائِدَةِ,
  سُورَةُ التِّينِ, سُورَةُ النَّاسِ и все три варианта басмалы. Заголовок
  суры 5 совпал с тем, что независимо лежит в данных V4.
- Сверка с живым API на страницах 1, 2, 50, 106, 187, 208, 221, 255, 300,
  597, 598, 604: множество строк-аятов из дампа совпало с ответом API.
  Расхождений 0.

### Две ловушки, на которых легко ошибиться молча

**Коды заголовков нельзя вычислять формулой.** `0xFB8C + N` даёт верный код
только для 37 сур из 114: на суре 38 в шрифте разрыв (U+FBB1 → U+FBD3).
Поэтому в репозитории лежит таблица, а не арифметика.

**Пробел в нумерации строк не говорит, что рисовать.** На странице 187
(сура 9) и на странице 208 пропущено по одной строке, но на первой это
заголовок, а на второй — басмала, потому что заголовок суры 10 остался на
предыдущей странице. Достраивание разметки «по дыркам» дало бы неверную
страницу Корана, и ни типы, ни сборка этого не поймали бы.

Отдельно про сам шрифт `QCF_BSML`: обычные арабские коды U+06xx в нём ведут
на пустую прямоугольную заглушку, хотя в `cmap` они присутствуют. Проверка
«есть ли символ в таблице кодировки» здесь врёт — сверять надо контур глифа.

## Ингушский перевод — 6236 записей

Источник — база `data/inh-quran/quran_translation_ing_smisl.db` (таблица
`translations`, версия `converted from xml 2024-08-10 08:08:44`), подробности и
URL — `data/inh-quran/README.md`. Перенесена в `translations.inh`
скриптом `scripts/replace-inh-source.mjs`. Арабский и Кулиев при этом не
тронуты.

**Сверка 2026-10-03** (вся база против `quran-sources.ts`):

- 6235 записей совпадают с базой посимвольно; отличие только в обрезанных
  пробелах по краям строки (`trim`), на экране они не видны;
- 50:45 пуст в самой базе — перевода нет;
- арабский и `translations.ru` во всех 6236 записях совпадают с версией до
  импорта.

**Аномалии источника** — что показывается вместо записи как есть
(фильтр `src/lib/inhTranslation.ts`, текст не правится):

| Аят | Что в записи после перевода | Что показываем |
|---|---|---|
| 20:32 | `<p>` и пусто | текст до `<p>` |
| 28:22 | `<p>` и символ U+F02B (квадрат) | текст до `<p>` |
| 78:36 | `<p>` и арабское «يَمْلِكُونَ» | текст до `<p>` |
| 87:5 | `<p>` и символ U+F09D (квадрат) | текст до `<p>` |
| 50:40 | `<p> 41. Iа ладувгIалахь…` — перевод 50:41 | текст до `<p>` |
| 50:41 | — (свой перевод приклеен к 50:40) | хвост записи 50:40 после `<p>`, без номера «41. » |
| 50:42–50:45 | в записях 50:41–50:44 (сдвиг на один до конца суры; в базе тафсира `ing_tafs` тот же сдвиг) | запись предыдущего аята дословно |

Перестановка конца суры 50 — решение владельца 2026-10-03, сверена по
смыслу с Кулиевым для каждого аята (`INH_REMAP` в
`src/lib/inhTranslation.ts`). Данные `quran-sources.ts` остаются точной
копией базы источника.

Проверяется тестом «Ингушский перевод: показ и поиск»
(`scripts/test-audio-model.mjs`): на экран не попадают разметка, символы
приватной зоны, арабские обрывки и номера аятов, показ — во всех 6236
аятах.

## Тафсир ас-Саади — 1658 фрагментов

`public/tafsir/saadi-ru/NNN.json` + `meta.json`, собирает
`scripts/gen/build-saadi-tafsir.py`, отчёт о сопоставлении —
`scripts/gen/data/saadi-tafsir-report.json`.

- **Текст** — ресурс 170 Quran Foundation, дословно (все 4742 непустые
  записи, каждая ровно один раз). У ресурса 170 непоследовательная привязка
  к аятам (запись то на последнем, то на первом аяте группы), поэтому сам
  API по аяту иногда отдаёт чужое (112:1 → тафсир суры 111).
- **Границы фрагментов** — QUL 310, как в книге («(1-6)»). Текст QUL не
  используется: в нём 24 278 разрывов слов от печатной вёрстки.
- Запись 170 относится к блоку QUL по содержанию (пробы по буквам);
  запись на два блока объединяет их (35 раз); блок QUL без толкования
  (только перевод аятов) присоединяется к предыдущему (47 раз); по позиции —
  2 записи (18:99, 34:6).
- Окно тафсира показывает аят(ы) фрагмента: арабский (как в ленте) +
  перевод + ссылка, затем толкование и атрибуцию.

## Где этот текст показывается

| Экран | Что берёт |
|---|---|
| Чтение суры (лента аятов) | арабский глифами QCF V4 + ингушский перевод + перевод Кулиева (каждый перевод скрывается и настраивается отдельно) |
| Закладки | превью — ингушский перевод (русский, если ингушский скрыт) |
| Окно «Тафсир ас-Саади» (кнопка у аята) | арабский как в ленте + ингушский/русский по настройкам + толкование ас-Саади |
| Поиск | ингушский перевод и перевод Кулиева (по 6236 аятов), один результат на аят |
| Азкары | собственные тексты владельца, не из этого реестра |

Глифы мусхафа (QCF V4, King Fahd Complex, мединский мусхаф 1441 г. х.)
описаны отдельно — `MUSHAF_FONTS.md`.

## Как перепроверить

```bash
npm run check:sacred
```

Сверяет пять контрольных аятов с сохранёнными снимками — ловит случайную
правку текста в данных. Полная сверка реестра с внешним источником делается
вручную по `editions` и `fetchedAt`.
